# معماری SPlusPy

## مرزهای اصلی

| مسیر | مسئولیت | احراز هویت |
|---|---|---|
| `spluspy.selfbot` | حساب کاربری و لایهٔ socket/MTProto | جریان ورود و session حساب |
| `spluspy.bot` | ربات رسمی و HTTP Bot API | توکن ربات |
| `spluspy.events` | مدل‌ها/رویدادهای سمت سلف‌بات | وابسته به کلاینت |
| `spluspy.filters` | فیلترهای قابل استفاده در هندلرها | بدون احراز هویت |
| `spluspy.middleware` | زنجیرهٔ میان‌افزار | وابسته به کلاینت |
| `spluspy.fsm` | مدیریت state و storage | مستقل از transport |
| `spluspy.plugins` | بارگذاری و مدیریت افزونه | وابسته به کلاینت |
| `spluspy.scheduler` | زمان‌بندی کارها | مستقل از transport |
| `spluspy.sessions` | ذخیره‌سازی session | محرمانه |

## اصول طراحی

1. از `spluspy.selfbot.Client` برای حساب کاربری و از `spluspy.bot.Bot` برای توکن ربات استفاده کنید.
2. دو کلاینت transport مشترک فرض نشوند؛ روش‌ها و مدل‌های رویداد ممکن است متفاوت باشند.
3. متدهای رسمی فقط زمانی قابل استفاده‌اند که API سمت سرویس آن‌ها را پشتیبانی کند.
4. نام‌های ریشه‌ای قدیمی (`Client`, `Robot`) برای سازگاری حفظ شده‌اند.
5. وابستگی‌های اختیاری برای PostgreSQL و Redis جدا از نصب پایه هستند.

## چرخهٔ عمر ربات رسمی

- `start()` برای اجرای async
- `stop()` برای توقف کنترل‌شده
- `close()` برای بستن منابع HTTP
- `start_webhook()` برای اجرای webhook در محیط async
- `run_webhook()` برای اجرای blocking در اسکریپت مستقل

از `run()` در داخل event loop از پیش فعال استفاده نکنید؛ در آن شرایط از APIهای async استفاده کنید.
